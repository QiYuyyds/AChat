# Capability: file-write-preview

## Overview

When an SDK Agent calls `fs_write`, the system SHALL render a live preview of the file content as it is being generated by the LLM. This provides real-time feedback during code/document generation. After the tool execution completes, the preview SHALL transition to a diff view (for modified files) or final content view (for new files).

### Requirement: Streaming Content Preview

The system SHALL produce a `file_write_preview` MessagePart when the CustomAdapter detects that the LLM is generating an `fs_write` tool call with `content` field. The content SHALL be streamed incrementally via `file_write_preview.append` PartDelta events.

#### Scenario: New file creation with streaming preview

- **WHEN** the CustomAdapter detects `tcd.function.name == "fs_write"` during tool_calls delta accumulation
- **THEN** the adapter SHALL yield a `part.start` event with `{ type: 'file_write_preview', path: '<extracted path or "">', content: '', callId: '<tool_call_id>', status: 'streaming', language: undefined }`
- **AND** for each subsequent args_buffer increment that contains content field data, the adapter SHALL yield a `part.delta` event with `{ type: 'file_write_preview.append', text: '<decoded content chunk>' }`

#### Scenario: Path extraction from args_buffer

- **WHEN** the `path` field in the args_buffer is extractable before content streaming begins
- **THEN** the adapter SHALL include the extracted path in the initial `part.start` event
- **AND** if the path is not yet extractable, the adapter SHALL set `path` to an empty string

#### Scenario: Content extraction state machine

- **WHEN** the adapter is tracking the `content` field value in the accumulating args_buffer
- **THEN** the adapter SHALL use a JSON string state machine that tracks the opening quote, escape sequences, and closing quote of the `content` field value
- **AND** the adapter SHALL decode JSON string escape sequences (`\"`, `\\`, `\n`, `\t`, `\r`, `\/`, `\uXXXX`) before emitting content chunks
- **AND** if the state machine fails to extract content (malformed JSON), the adapter SHALL silently skip further delta events and let the tool.result provide the final state

### Requirement: Preview Completion with Diff Data

When `fs_write` or `fs_edit` execution completes successfully, the system SHALL update the `file_write_preview` part with completion data including diff information.

#### Scenario: Tool execution completes for file modification

- **WHEN** `_execute_tool_call_to_result` executes `fs_write` successfully and the file previously existed
- **THEN** it SHALL append a `FileWritePreviewCompleteEvent` with `{ path, oldContent: '<previous file content>', newContent: '<written content>', status: 'complete' }`
- **AND** `consume_stream` SHALL update the corresponding `file_write_preview` part in `parts_buffer` with `status: 'complete'`, `oldContent`, and `newContent`
- **AND** `consume_stream` SHALL publish a SSE event to update the frontend

#### Scenario: Tool execution completes for new file

- **WHEN** `_execute_tool_call_to_result` executes `fs_write` successfully and the file did not previously exist
- **THEN** it SHALL append a `FileWritePreviewCompleteEvent` with `{ path, oldContent: null, newContent: '<written content>', status: 'complete' }`

#### Scenario: Tool execution fails

- **WHEN** `fs_write` execution fails (error or rejection)
- **THEN** it SHALL append a `FileWritePreviewCompleteEvent` with `{ path, oldContent: null, newContent: null, status: 'failed' }`

### Requirement: Graceful Degradation

The streaming preview SHALL degrade gracefully when content extraction is not possible.

#### Scenario: Partial JSON extraction failure

- **WHEN** the state machine cannot reliably extract content from the args_buffer (e.g., malformed JSON, unexpected field order)
- **THEN** the `file_write_preview` part SHALL remain in its current state (possibly empty content)
- **AND** the tool execution SHALL proceed normally without any preview
- **AND** the final `FileWritePreviewCompleteEvent` SHALL still be emitted and update the part with diff data

### Requirement: Applicability Scope

The streaming preview SHALL only apply to SDK Agent `fs_write` tool calls via the `call_once` path.

#### Scenario: CLI Agent fs_write call

- **WHEN** a CLI Agent (Claude Code / Codex) calls `fs_write`
- **THEN** no `file_write_preview` part SHALL be produced
- **AND** the tool.result SHALL still contain `oldContent` / `newContent` for ToolUsePart diff rendering (Direction B)

#### Scenario: CustomAdapter stream mode

- **WHEN** CustomAdapter's `stream` method (legacy self-loop) is used
- **THEN** no `file_write_preview` part SHALL be produced
- **AND** the tool.result SHALL still contain `oldContent` / `newContent` for ToolUsePart diff rendering
